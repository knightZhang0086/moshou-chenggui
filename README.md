# 墨守成规

中文双人连线桌游，v0.4.1。包含本地热座、简单人机、邀请码双人实时对战；完整九攻/九拒18张技能、按赛制公开抽2/3/4/5张、局间削弱与三/五/七/九局赛制。

## 无依赖运行

安装 Node.js 22 或更新版本，在项目目录执行：

```sh
node server.mjs
```

打开 http://localhost:4173 。无需 npm install，无第三方运行依赖。
同一局域网可让第二台设备打开主机 IP 的 4173 端口（需系统允许入站连接）；公网使用下述 HTTPS 部署。

```sh
node --test *.test.mjs
node simulate.mjs 60
node docs.mjs
node build.mjs
```

## 分享规则

- `RULEBOOK.md`：独立中文规则书，与游戏共用定义生成。
- `rulebook.html`：可浏览、打印的完整规则与牌库。
- `RULEBOOK.pdf`：已生成的中文 PDF。
- `BALANCE.md`：规则补充、参数、模拟结果和待验证问题。
- `TEST-REPORT.md`：测试证据与已知限制。

## 部署方式 A：同域完整服务（建议）

将整个项目部署至支持长连接的 Node 或 Docker 主机，运行 `node server.mjs`，配置持久化目录 `DATA_DIR`。前端与在线接口同域，不需另填服务器地址。

```sh
docker compose up -d --build
```

用托管平台提供的 HTTPS 域名访问，或在自有服务器配置 HTTPS 反向代理。代理须关闭 SSE 缓冲，允许长连接，读取超时至少60秒；服务器每15秒发一次心跳。

Render Blueprint 文件已提供。导入仓库后创建 Web Service，使用 Docker，健康检查 `/api/health`，持久化磁盘挂载 `/data`。`render.yaml` 使用需要付费的 starter 与磁盘；请在平台核对费用并自行确认购买。本次任务不会擅自购买服务。若不用磁盘，容器重新部署会丢失房间；不应声称支持跨部署重连。

## 部署方式 B：GitHub Pages + 单独对战服务器

1. 执行 `node build.mjs`，将 `dist/` 内容发布到 Pages。网页可独立热座、人机、查规则。
2. 按方式 A 部署服务端，配置 `ALLOWED_ORIGINS=https://你的账号.github.io`。多个来源以英文逗号分隔，不带末尾斜杠。
3. Pages 的“千里邀局 → 在线服务器设置”填入服务端 HTTPS 来源地址，保存并检测。
4. 创建房间并复制邀请，朋友打开后确认服务器地址，再凭邀请码加入。
5. 用两个独立浏览器验证落子同步、刷新恢复与断线重连。

GitHub Pages 只提供静态托管，不能单独运行 `server.mjs`。未部署后端时，不能称邀请码公网联机已上线。

## 在线服务设计

- HTTP POST 提交行动，SSE 持续推送局面，服务端使用同一规则引擎验证。
- 六位随机邀请码；红蓝各有256位随机座位凭证，仅客户端持有明文；服务器存 SHA-256 摘要。
- 凭证放在 Authorization 请求头，不放 URL；房间邀请码可分享，座位凭证不可分享。
- 浏览器本地保存座位凭证，刷新或断线后重连获取完整快照；无法凭邀请码抢占满房间。
- 版本号防过期操作；最近64条请求编号去重，网络重试不重复扣木。
- 同步原子文件写入完成后才广播；重启保留状态。单进程部署，不支持多副本共享文件目录。
- 默认最大1000房间；单IP每分钟300次请求；每房间最多8条SSE连接。位于反向代理后按连接IP限流，很多用户共享代理会共用额度；规模化部署应改为可信代理IP配置和数据库。
- 未加入房间离线2小时回收，进行中离线且无行动48小时回收，关闭房间6小时回收。没有按现实秒数的回合时限。
- 不包含账号、聊天、排名、匹配、跨设备座位迁移或反作弊身份系统；同设备多个标签页共用座位，双人测试请用两个独立浏览器存储环境。

## 文件布局

`engine.mjs` 规则及AI；`rules.mjs` 规则书与牌文；`app.mjs` 交互；`server.mjs` 房间、鉴权和推送；`*.test.mjs` 规则与网络集成测试；`` 可复现生成与模拟。

所有卡牌、边界条件与每步耗木都由引擎决定。修改规则后同步更新说明与测试，运行文档生成再发布。

## GitHub 网页发布布局

本仓库采用平铺文件布局，方便通过 GitHub 网页上传。服务端严格白名单只提供网页文件，不提供房间数据、测试或服务端源码。可直接在仓库根目录运行 `node server.mjs` 和 `node --test *.test.mjs`。原始分目录工程另见下载包。
